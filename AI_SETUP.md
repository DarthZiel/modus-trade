# ИИ-помощник

Локально включён `AI_PROVIDER=demo`: это явно обозначенные шаблоны без модели.
Данные не передаются внешним сервисам. Для реального ИИ добавьте в корневой `.env`:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=<ключ OpenAI API>
OPENAI_MODEL=gpt-4o-mini
```

Применить: `docker compose up --build -d --wait --wait-timeout 180`.
Отключить: `AI_PROVIDER=disabled`. Сайт и подача без ИИ продолжают работать.

Для OpenAI используется Responses API со Structured Outputs и `store=false`.
Для OpenRouter — отдельный адаптер Chat Completions. В обоих случаях ответ
проверяется серверной схемой, запрос по умолчанию ограничен 20 секундами и
2500 выходными токенами; автоматического повтора платного запроса нет.
За 5 минут одному сотруднику доступны до 10 запросов (лимит MVP в одном процессе).
Входной текст считается данными: модель не получает инструментов изменения БД.
Передаётся только описание, тип и явно введённые уточнения; для плана — заголовок
и описание выбранного обращения. Профиль, имена ответственных, переписка и файлы
не отправляются. Перед внешним запросом интерфейс и бот запрашивают согласие с названием
выбранного сервиса. Для OpenRouter текст также получает провайдер выбранной модели.

Сценарий: описание → отдельное предложение → максимум два вопроса → ответы
(необязательно) → проверка автором → явное применение → обычный предпросмотр
и подача. Ничего не публикуется от имени автора автоматически. Исходное описание
сохраняется в обращении и раскрывается в карточке, если итоговый текст отличается.
Новые числовые утверждения без источника отклоняются; остальные факты всё равно
требуют проверки человеком. Структурированная схема сама по себе не доказывает
достоверность текста. Ошибка модели не стирает форму или черновик бота.

Черновик эксперимента не запускается автоматически, не подставляет даты, людей,
затраты или достигнутые результаты. Ответственный проверяет и утверждает план.
В деморежиме предлагается общий шаблон, который нужно конкретизировать вручную.

Проверена интеграция с подменённым клиентом без платных вызовов. По ответу
пользователя реальный ключ будет позже; живая проверка OpenAI пока не выполнена.

Официальная основа интеграции: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).


## OpenRouter: выбор моделей без изменения кода

Заполните корневой `.env`:

```dotenv
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=<ключ OpenRouter>
OPENROUTER_MODEL=<точный ID выбранной модели>
# Необязательно: отдельная модель для планов, иначе используется основная.
OPENROUTER_EXPERIMENT_MODEL=
OPENROUTER_OUTPUT_MODE=schema
AI_TIMEOUT_SECONDS=20
AI_MAX_OUTPUT_TOKENS=2500
```

ID копируется из [каталога OpenRouter](https://openrouter.ai/models), включая
префикс организации и суффикс варианта, если он есть. Список моделей в коде
не зашит. Ключ OpenAI не нужен. Модель для обращений и модель для экспериментов
могут относиться к разным семействам. В интерфейсе виден выбранный ID.

Режим ответа выбирается явно:

| OPENROUTER_OUTPUT_MODE | Как работает |
|---|---|
| `schema` | Строгая JSON Schema; требуется поддержка моделью и провайдером |
| `json` | JSON-объект; соответствие полям проверяется приложением |
| `prompt` | JSON запрашивается инструкцией, без параметра response_format; проверка схемы остаётся обязательной |

Начните с `schema`. Если выбранная модель не поддерживает этот режим, выберите
`json` либо `prompt` и проверьте результат. Неподходящий, неполный ответ или отказ
модели не применяется к обращению. Приложение не переключает модель и не повторяет
запрос автоматически; смена режима тоже требует явного изменения настройки.
OpenRouter может выбирать поставщика самой модели по своим правилам маршрутизации.
В schema/json отправляется `provider.require_parameters=true`, чтобы параметры
формата не были молча проигнорированы при выборе поставщика.

После смены модели, режима или ключа:

```sh
docker compose up --build -d --wait --wait-timeout 180
```

Затем обновите страницу Mini App / сайта. При работе бота выберите заново помощь
с формулировкой. Вложения и профиль по-прежнему не передаются. Настройки обработки
данных у OpenRouter и поставщиков задаются отдельно на стороне этих сервисов;
параметр OpenAI `store=false` не является общей гарантией для OpenRouter.

Проверены реальные HTTP-контракты SDK на MockTransport, без внешних запросов:
три режима, произвольный ID, отдельная модель плана, ошибки, отказы, обрезанные и
невалидные ответы, отсутствие автоматических повторов. Живая проверка выбранной
модели потребует ключа и её доступности в аккаунте.

Официальная документация: [Structured Outputs](https://openrouter.ai/docs/guides/features/structured-outputs),
[API](https://openrouter.ai/docs/api_reference/overview),
[маршрутизация по поддерживаемым параметрам](https://openrouter.ai/docs/guides/routing/provider-selection#requiring-providers-to-support-all-parameters).
