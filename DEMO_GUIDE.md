# Демонстрация Modus Feedback за 5–7 минут

## Подготовка

Откройте [локальный сайт](http://localhost:5173/). Демонстрационные аккаунты
и пароль находятся в локальном `.demo-credentials.json` (права 600, исключён
из Git). Не публикуйте этот файл. Для показа без переключения аккаунтов удобно
открыть отдельные профили браузера для сотрудника, координатора и ответственного.

Демо-данные — синтетические, не сведения о работе или показателях ГК «Модус Трейд».
Для автономной демонстрации можно выбрать `AI_PROVIDER=demo`: интерфейс
обозначает шаблоны без модели. Внешние подключения зависят от окружения;
текущий режим смотрите в интерфейсе, не выдавайте локальный режим за живой ИИ.

Если демонстрационный набор ещё не создан:

```sh
docker compose exec backend python -m app.demo
```

Команда попросит пароль минимум 12 символов и создаст только отдельную компанию
«ДЕМО — Modus Feedback», три аккаунта и пять обращений. Повторный запуск не
создаёт дубликатов. Аккаунты:

- `demo.employee@example.com` — сотрудник;
- `demo.coordinator@example.com` — координатор;
- `demo.responsible@example.com` — ответственный.

## Сценарий для жюри

### 1. От сообщения к понятному обращению — 1 минута

Под сотрудником создайте проблему: «На складе похожие коробки стоят без маркировки,
на второй полке их трудно различать». Нажмите **Предложить формулировку**.
Покажите отдельное предложение и два вопроса. Ответьте, например, где это происходит
и что хочется изменить. Нажмите **Учесть мои ответы**, затем
**Проверил — применить**. До этого момента исходная форма не меняется.
Проверьте обращение и отправьте. В карточке раскройте исходный текст автора.

Фраза для выступления: «Сотруднику не нужно знать ответственного или писать
идеальное служебное письмо. Помощник готовит черновик; сотрудник контролирует,
что именно будет отправлено. Здесь мы показываем локальный деморежим».

### 2. Понятная ответственность — 1 минута

Под координатором откройте очередь. Покажите счётчики: без ответственного,
просроченные, эксперименты, ожидающие подтверждения, подтверждённые авторами.
Назначьте ответственному новое обращение и срок ответа. Перенос срока требует
объяснения и сохраняется в истории. Автор видит, кто и когда должен ответить.
Откройте уведомления: карточка доступна одним переходом.

### 3. Проверить изменение экспериментом — 2 минуты

Под ответственным откройте назначенную идею или проблему. Нажмите
**Подготовить эксперимент**, затем **Предложить черновик плана**.
Шаблон не запускается автоматически: проверьте его и конкретизируйте:

- гипотеза: маркировка помогает различать похожие коробки;
- изменение: подписать одну полку;
- критерий успеха: автору удобно различать коробки во время обычной смены;
- срок: небольшой интервал для проверки;
- исходное измерение: оставьте пустым, если его действительно нет.

Утвердите план. Затем **Зафиксировать итог проверки**, запишите действия,
наблюдения и выберите «Внедрить шире», «Доработать» или «Прекратить».
Покажите надпись **«Количественный эффект не подтверждён»**, если измерений нет.
Для сравнения в начальном наборе есть завершённая проверка с явно синтетическими
измерениями 12 → 3; система показывает разность, а не выдуманную экономию в рублях.

Фраза: «Принять идею — ещё не значит внедрить. Мы фиксируем проверку и её
результат, отделяя наблюдения от обещаний».

### 4. Результат подтверждает сотрудник — 1 минута

Завершение эксперимента само по себе не закрывает обращение. Зафиксируйте решение
в разделе рассмотрения. Под сотрудником оставьте комментарий к эксперименту и
нажмите **Помогло** или **Проблема осталась**. Возврат требует комментария;
предыдущие решения остаются в истории. Только подтверждение автора закрывает
выполненное обращение. Молчание автора не считается успехом.

### 5. Показать защиту от «забыли» — 30 секунд

В начальном наборе есть просроченное обращение. Откройте фильтр просрочек и центр
уведомлений. Напоминания проверяются раз в минуту и не повторяются при каждом
запуске. Для эксперимента есть отдельное напоминание о сроке, для автора — одно
напоминание через три дня ожидания подтверждения.

## Главное отличие

Показывайте единый цикл: **проблема → ответственный и срок → небольшая проверка →
зафиксированный результат → подтверждение сотрудника**. Бот и CRUD обслуживают
этот цикл. Не обещайте доказанную экономию, если нет измерений, и не выдавайте
деморежим за работающую модель.

## Пересоздание демо

```sh
docker compose exec backend python -m app.demo --clear
docker compose exec backend python -m app.demo
```

Удаляется только демонстрационная компания. Если добавлены другие пользователи
или вложения, очистка останавливается. Другие компании не затрагиваются.
Команды не запускаются автоматически при старте сервиса.


## Повторы, статистика и датасет организатора

Дополнительный набор: `docker compose exec backend python -m app.hackathon_demo`.
Введите отдельный демонстрационный пароль и войдите под
`dataset.coordinator@example.com`. Выберите компанию «ДЕМО — Датасет хакатона»
в статистике. Набор содержит 20 исходных и 4 добавленных синтетических обращения,
девять аккаунтов, даты первого ответа, просрочки, подтверждение и возврат.
Повторная загрузка не сбрасывает проведённый показ.

1. В очереди найдите «Разные наименования мешают найти карточку изделия»
   (`EXT-022` в описании). Запустите поиск похожих. Для настоящей модели
   подтвердите передачу текстов; `demo` использует слова и явно это сообщает.
2. Сопоставьте с «Единые обозначения изделий в номенклатуре» (`A-003`),
   выберите «Одна проблема» и подтвердите связь. Откройте повторяющиеся
   проблемы: группа содержит обращения от нескольких сотрудников.
3. Покажите A-004 и A-016: обе темы об обучении, но разные предложения.
   Подготовленная связь имеет тип «Связанная тема» и не создаёт группу дублей.
4. В статистике покажите среднее время первого ответа, отсутствие ответа,
   просрочки, подтверждённый результат и возврат. Нажмите показатель —
   откроется список обращений, на которых он рассчитан.
5. Смените подразделение и даты, покажите недельную динамику и категории.
   Объясните, что все показатели этого набора синтетические. В разделе
   «Как считаются показатели» доступны точные определения.

На первом запуске подготовлена одна подтверждённая пара A-003 / EXT-021
и одна ещё не подтверждённая тематическая связь A-004 / A-016. Они подписаны
как материал демонстрации, а не результат модели. Новые ответы модели могут
отличаться; координатор оценивает смысл и не обязан подтверждать предложения.


## Кабинет директора

1. Выполните `docker compose exec backend python -m app.director_demo`
   и задайте пароль нового директора `dataset.director@example.com`.
   Основной датасет остаётся изолированным; после расширения — 27 обращений.
2. Войдите под директором. В «Требуют внимания» покажите непроверенное
   подозрение на пропажу оборудования: требуется проверка, не обвинение.
3. В обычной очереди покажите пожелание о печенье и обещание «+300%»
   без механизма. Они сохранены, но не занимают верх приоритетной подборки.
4. В «Перспективных идеях» есть конкретная памятка межотдельного процесса,
   которую можно проверить небольшим экспериментом. Перейдите в статистику:
   используются те же реальные поля системы и синтетические данные набора.
5. Под координатором откройте обращение директора, получите оценку ИИ
   с отдельным согласием и исправьте приоритет с объяснением. Директор увидит
   обновление. Новый ответ ИИ не заменит ручной выбор; покажите сравнение
   и историю. При необходимости явно верните предложение ИИ.

Директор читает данные своей компании и не получает права изменять чужую
переписку или подтверждать результат за автора. Координатор может совмещать
роль директора; полномочия ролей складываются. Все примеры синтетические.
