# Подключение Telegram и Mini App

Код подготовлен для подключения; без бота и публичного HTTPS-адреса локальный
сайт продолжает работать. Токены не нужны для автоматических тестов.

## Что заполнить сейчас

Личный Telegram ID в .env не нужен: бот узнает его при одноразовой привязке
через сайт. Нужны BOT_TOKEN, BOT_USERNAME и публичный HTTPS-адрес MINI_APP_URL.
BOT_API_SECRET уже сгенерирован в локальном .env; это внутренний секрет, его не
нужно искать в Telegram. Токены вводите в .env, не отправляйте в чат.

Для OpenRouter укажите OPENROUTER_API_KEY, OPENROUTER_MODEL и AI_PROVIDER=openrouter.
Ключ OpenAI для этого не нужен. Выбор модели и режима описан в AI_SETUP.md.
Настройка ИИ не зависит от подключения Telegram.

## 1. Создать и настроить бота

1. В официальном [@BotFather](https://t.me/BotFather) выполните `/newbot`.
2. Сохраните токен только в локальном `.env` в корне проекта:

   ```dotenv
   BOT_TOKEN=<токен BotFather>
   BOT_USERNAME=<username без @>
   BOT_API_SECRET=<отдельная случайная строка минимум 32 символа>
   MINI_APP_URL=https://feedback.example.com
   COOKIE_SECURE=true
   ```

   Отдельный секрет можно сгенерировать командой:
   `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`.
   Это секрет обмена между ботом и API, не токен BotFather.
3. Опубликуйте frontend и `/api/` на одном HTTPS-домене. `MINI_APP_URL` — только
   origin, без `/mini`, query и fragment. Локальный `http://localhost:5173`
   для рабочего запуска Telegram не подходит. При временном HTTPS-туннеле
   направьте его на frontend (порт 5173), который уже проксирует `/api/`.
4. По желанию настройте Menu Button в BotFather (`/setmenubutton`):
   текст «Кабинет», адрес `https://feedback.example.com/mini/appeals`.
   Кнопки Mini App в личном чате бот создаёт сам; настройка Main Mini App
   не обязательна для этого сценария.
5. Запустите:

   ```sh
   docker compose --profile bot up --build -d --wait --wait-timeout 180
   docker compose logs --tail=30 bot
   ```

Бот использует long polling: Telegram webhook настраивать не нужно.
Один экземпляр бота обслуживает один токен. Не запускайте одновременно второй
polling-процесс с тем же токеном. Настройки бота получает и backend; после
изменения `.env` примените команду запуска ещё раз.

## 2. Привязать сотрудника

1. Координатор приглашает сотрудника обычным приглашением на сайт.
2. Сотрудник активирует аккаунт, входит на сайт и нажимает **Telegram** в шапке.
3. Нажимает **Привязать Telegram** → **Открыть бота и привязать аккаунт** →
   **Старт** в своём личном чате. Ссылка одноразовая, действует 10 минут.
   Новая ссылка заменяет предыдущую. Не пересылайте ссылку другим людям.
4. Бот подтверждает имя аккаунта. В кабинете можно нажать
   **Проверить подключение**; при возврате в окно статус также обновляется.
5. Кнопка **Открыть кабинет** в боте запускает общий интерфейс Mini App.
   Пароль отправлять боту не нужно. Без привязки Telegram не создаёт аккаунт
   и не выдаёт доступ в систему.

Один Telegram ID связан с одним сотрудником. Сменить привязку можно только
после отключения прежней на сайте. Отключение отзывает все сеансы Mini App,
удаляет черновик бота, прекращает доступ бота и сохраняет обращения. Обычная
сессия сайта остаётся действительной. Если отключить прямо из Mini App,
потребуется снова войти на сайт по паролю.

## 3. Сценарии бота

- `/start`: меню; `/help`: помощь; `/cancel`: отмена черновика или ответа.
- Проблема / идея → текст описания → до 5 фото или файлов по 10 МБ →
  предпросмотр → **Отправить исходный текст**. До отправки можно исправить
  описание, убрать все вложения или отменить. Черновик хранится в PostgreSQL,
  кнопка **Продолжить черновик** восстанавливает его после перезапуска.
- Заголовок формируется из первых 160 символов описания, категория — «Другое».
  Для самостоятельного заголовка и категории используйте форму Mini App.
  Проверку фактического формата вложений выполняет общий API (PDF, JPG, PNG,
  WebP), как на сайте. Фото с подписью не заменяет отдельное описание.
- **Мои обращения**: страницы по 5 → краткая карточка → полная карточка Mini App.
- **Ответить по обращению**: бот явно указывает номер и ожидает текст ответа.
  Произвольный текст без выбранного обращения не публикуется в переписку.
- **Помогло** / **Проблема осталась**: доступны автору при ожидании подтверждения.
  Возврат требует комментария. Устаревшее решение вызывает конфликт версии.
- Помощь с формулировкой: отдельное предложение, максимум два уточнения и явное
  применение. При режиме openai перед передачей текста бот просит согласие;
  режим demo явно обозначен как локальные шаблоны без модели.

## 4. Уведомления

Существующий центр уведомлений остаётся основным журналом. Привязанный бот
забирает новые уведомления через внутренний API раз в 15 секунд и отправляет
номер, тип события и кнопку перехода. Накопленные до привязки уведомления
не рассылаются. Доступ проверяется повторно: неактивный сотрудник и прежний
ответственный не получают новые доставки по недоступному обращению.

Запись временно закрепляется за процессом на 5 минут. После подтверждения
успеха повторная доставка не производится. При временной ошибке — до 5 попыток;
после блокировки бота отправка для привязки отключается. Для восстановления
разблокируйте бота, отключите привязку на сайте и создайте новую.

При обрыве связи **после** принятия сообщения Telegram, но **до** фиксации
подтверждения возможна повторная доставка: Bot API не предоставляет ключ
идемпотентности для отправки сообщения. Действия по обращению защищены от
дубликатов независимо от доставки уведомлений. Чтение уведомления в вебе
не зависит от факта доставки в Telegram.

## 5. Безопасность и авторизация Mini App

Сервер проверяет `initData` по HMAC-SHA-256 с токеном бота, `auth_date`
(не старше 5 минут; допуск часов в будущем 30 секунд), уникальность полей
и Telegram ID. `initDataUnsafe` для авторизации не используется. После
проверки выдаётся сеанс на 8 часов, роли берутся из текущей записи сотрудника.
При истечении launch-данных нужно заново открыть Mini App из бота.

Mini App использует токен сеанса в памяти страницы и заголовок Authorization,
чтобы работать и при блокировке сторонних cookies в Telegram Web. В
localStorage токен не записывается. Для обычного сайта сохраняется HttpOnly
cookie. Привязка не меняет роли сотрудника; блокировка аккаунта немедленно
запрещает работу и на сайте, и в боте, и в Mini App.

Внутренние `/internal/telegram/*` требуют отдельный `X-Bot-Secret`.
Бот передаёт Telegram ID отправителя, который сервер сопоставляет с привязкой;
создание обращений, сообщений и оценок проходит через общие обработчики API.
Секреты не должны попадать в frontend, логи запросов или репозиторий.

Документация: [проверка Mini App initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app),
[deep links](https://core.telegram.org/bots/features#deep-linking).

## 6. Проверка после подключения

1. Создайте двух сотрудников и одного ответственного по приглашениям.
2. Привяжите Telegram первого сотрудника; проверьте отказ при попытке
   привязать тот же Telegram ко второму.
3. Создайте проблему с фото в боте — она должна появиться на сайте и в Mini App.
4. Назначьте ответственного на сайте — автору должно прийти уведомление.
5. Запросите уточнение, ответьте из карточки бота и проверьте общую переписку.
6. Зафиксируйте результат → верните из бота с комментарием → зафиксируйте новый
   результат → подтвердите в Mini App.
7. Отключите Telegram на сайте: открытый сеанс Mini App и действия бота должны
   перестать работать; обычный вход и обращения на сайте должны сохраниться.

Эта живая проверка требует настоящего бота и HTTPS и пока не выполнена.
Локальные тесты проверяют API и сценарии диалога без запросов к Telegram.

```sh
# backend: отдельная БД modus_test, как описано в README
 docker compose run --rm --no-deps -e DB_NAME=modus_test backend uv run --frozen python -m pytest -q tests
# бот: автономные тесты без токена
 cd bot
 uv run --frozen python -m pytest -q tests
```
